# AVOID.NET — Design Language

**Status:** living document · **Owner:** chadjective · **Last revised:** 2026-05-04

This is the canonical design doc for AVOID.NET. Every page that renders
to a public reader must obey it. Pairs with [docs/SPEC.md](../docs/SPEC.md)
(system spec) and [docs/HACKATHON_ROADMAP.md](../docs/HACKATHON_ROADMAP.md)
(execution plan).

The `avoid-design` Claude skill is the invokable deep-reference version
for design sessions.

---

## 1. Brand essence (one paragraph)

AVOID.NET is a verified-claims index for the post-truth era. AI drafts
the case file; the community verifies it; Solana anchors the audit log.
The product looks and feels like a **declassified dossier in a terminal**
— monospace, dotted borders, grid background, bracket-status labels.
Trustworthy because it shows its work, not because it asserts authority.

## 2. Audience

**Crypto-first → mainstream-second.**

- **Phase 1 (now / hackathon):** crypto-native users. Comfortable with
  on-chain audit trails, ZachXBT, scam-flagging vocabulary.
- **Phase 2 (target):** their parents, friends, anyone who's been sent a
  link. Has zero crypto context. May be evaluating microplastics or a
  cookware recall.

Every public page must be **legible to a non-crypto reader who arrived
via a shared link.** This kills jargon, demands plain-English summaries,
and makes Open Graph previews load-bearing.

## 3. Tagline canon

| Slot | Phrase | Where it appears |
|------|--------|------------------|
| **Primary** | **Avoid your next big mistake.** | Homepage hero, OG previews, page titles |
| **Positioning** | Verified advice for a post-truth world. | Sub-hero, About page, footer |
| **Mechanism** | Collective Intelligence > Artificial Intelligence | Tertiary tagline near CTAs |
| **Action** | Do diligence better together. | Submit-evidence flow, About |

Primary tagline plays the brand-as-verb (`Avoid` → action). Period adds
gravity. Use sparingly — never two taglines on the same surface.

## 4. AI/community framing

**Canonical phrase: "AI-drafted, community-verified."**

The AI is the journalist. The community is the editor. Solana is the
notary. Frame this as the *feature*, not an apology.

- ❌ "Generated by AI — Human review pending" *(apologetic)*
- ✅ "AI-drafted · community-verified · Solana-anchored" *(confident)*

For drafts not yet reviewed: a **status pill** at the top
(`AI-DRAFTED · AWAITING VERIFICATION`), not an amber warning banner.

## 5. Voice

- **Plain English, second-person.** "You should avoid this." not "It is
  recommended that…"
- **Concrete over abstract.** "Lost $2.4B in customer funds" beats
  "Significant solvency issues."
- **Sourced, not editorialized.** State the claim, link the receipt.
- **No exclamation points.** No emoji in body copy.
- **Mono for data, sans for prose.** Hashes, addresses, signatures,
  timestamps, slot numbers, status labels → mono. Narrative → sans.

## 6. Visual language

The aesthetic is **declassified-dossier-meets-terminal.**

- **Dotted borders** on cards and CTAs (`border-dashed`).
- **Subtle grid background** (faint dot grid or 1px line grid, ~5% opacity).
- **Bracket-status labels** (`[WARNING]`, `[DISPUTED]`).
- **Terminal-style entity refs** (`avoid.net/aws → 75/100 80% conf.`).
- **No gradients, no glassmorphism, no shadows.** This is paper and ink,
  not material design.
- **No saturated brand-blue.** Blue is the off-brand color.

## 7. Type system

**Fonts:** `font-mono` (Geist Mono) is primary for the brand. `font-sans`
(Geist Sans) is the body fallback for narrative prose. *Do not use Arial
or system-ui anywhere — replace any usage on sight.*

```
Display / hero    Geist Mono, 600 weight, tracking-tight
Headings          Geist Mono, 600 weight
Data / labels     Geist Mono, 500 weight, uppercase, tracking-wider
Body prose        Geist Sans, 400 weight, leading-relaxed
Inline code/data  Geist Mono, 400 weight, no background tint
```

Hierarchy: never more than **3 type sizes per surface.**

## 8. Color tokens

Dark by default. Light mode is post-hackathon.

| Token | Hex | Use |
|-------|-----|-----|
| `bg-base` | `#0a0a0a` | Page background |
| `bg-grid` | `rgba(255,255,255,0.04)` | Grid overlay dots |
| `border-default` | `#27272a` (zinc-800) | Default dotted border |
| `border-muted` | `#1f1f23` | Subtle dividers |
| `text-primary` | `#ededed` | Body |
| `text-secondary` | `#a1a1aa` (zinc-400) | Captions, metadata |
| `text-muted` | `#71717a` (zinc-500) | Tertiary, disabled |
| `accent-warning` | `#f97316` (orange-500) | WARNING / high severity |
| `accent-critical` | `#ef4444` (red-500) | CRITICAL |
| `accent-caution` | `#eab308` (yellow-500) | CAUTION / medium severity |
| `accent-verified` | `#22c55e` (green-500) | LOW RISK band / ✓ FACT-CHECKED pill / low severity |
| `accent-disputed` | `#a855f7` (purple-500) | DISPUTED (orthogonal to severity) |

**Banned:** any saturated blue (`text-blue-*`, `bg-blue-*`,
`border-blue-*`). Use `accent-verified` (green) for trust-positive states
and `text-secondary` for neutral links.

## 9. Component patterns

### Card

```
border: 1px dashed border-default
border-radius: 4px (sharper than default)
padding: p-6
no shadow, no gradient
optional: severity edge bar (left edge, 2px wide)
```

### Button

Three tiers, all bordered + dashed:

| Tier | Use | Style |
|------|-----|-------|
| **Primary** | Single page-level CTA | dashed border, mono, uppercase, on hover: solid border |
| **Secondary** | Peer actions (Browse / Submit / How) | dashed border, sentence case |
| **Tertiary** | Inline links | dotted-underline, no border |

**No solid filled buttons.** No saturated colors.

### Status pill (`[BRACKET]` style)

```
font: mono uppercase
border: 1px dashed (color matches semantic)
padding: 2px 6px
text: tracking-wider, text-xs
```

Always wrapped in literal brackets in markup (`[WARNING]`).

### Severity edge bar

For per-section severity (axis C below): a 2px vertical color bar on
the *left edge* of the card. Never a pill badge. Color comes from the
severity → color map.

### Trust score gauge

Hero element on investigation pages. Numeric center, ring around it,
band label below in brackets.

## 10. Taxonomy — four axes, four treatments

Four distinct semantic axes. Each gets a **visually distinct** treatment
so they cannot be confused.

| Axis | Question | Values | Treatment |
|------|----------|--------|-----------|
| **A. Entity trust** | "How risky is this thing?" | 0–100 + band: CRITICAL · WARNING · CAUTIONARY · LOW RISK | **Numeric ring gauge** + bracket band label |
| **B. Page lifecycle** | "How settled is this assessment?" | AI-DRAFTED · UNDER REVIEW · ✓ FACT-CHECKED · DISPUTED | **Bracket status pill** in mono |
| **C. Section severity** | "How bad is this specific issue?" | low / medium / high / critical | **Vertical edge bar** on card left, no label |
| **D. Evidence status** | "Is this submission accepted?" | under_review / accepted / rejected / revoked | **Inline muted text** per row |

**Critical rule:** A and B are orthogonal. A high-trust page can be
UNDER REVIEW; a low-trust page can be ✓ FACT-CHECKED. They must look like
different kinds of things.

## 11. CTA hierarchy

Stigmergy is the product, but **most visitors arrive to consume**.
Don't lead with `EDIT THIS PAGE`.

**Pattern: contextual + persistent, not blocking.**

1. **Top right of investigation page**: small `+ evidence` button
   (secondary tier, dashed border, no saturated color).
2. **End of each section**: inline contextual prompt — "Have evidence
   about [section topic]? →"
3. **Submission stats panel**: hides when 0/0/0. Empty state is one
   line: "No evidence submitted yet — be the first."
4. **No full-width primary blue CTA above the fold.** Ever.

## 12. Anti-patterns

- ❌ `bg-blue-*`, `text-blue-*`, `border-blue-*` (any saturated blue)
- ❌ Arial, Helvetica, system-ui as body font
- ❌ Solid filled buttons
- ❌ Box shadows, gradients, glassmorphism
- ❌ Emoji in body copy or status labels
- ❌ Pill badges for section severity (axis C)
- ❌ Amber "Generated by AI — Human review pending" (use lifecycle pill)
- ❌ Mixing severity (A) and lifecycle (B) labels under one taxonomy
